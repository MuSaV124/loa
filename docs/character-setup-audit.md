# XXAPICK 캐릭터 분석 탭 장비 표시 감사

기준 `1b9b628` · 브랜치 `codex/xxapick-character-setup`

## 원인과 수정

장비 정보는 기존 API가 `powerSnapshot`으로 파싱하고 있었다. Git 이력에서 확인한 장비 행의 기존 렌더러는 시뮬레이터의 장비 파싱 영역에서 호출된다. 캐릭터 라우팅이 추가된 `d249c74`의 분석 화면 패널 목록에는 캐릭터 카드, 계산 요약, 예리한 둔기만 있었다. 캐릭터 분석 화면에 장비 표시 호출이 없었으므로 API 응답이 정상이어도 장비가 나타나지 않았다. CSS 숨김이나 마나 쪽 오류로 장비가 사라진 흔적은 확인하지 못했다.

분석 탭 전용 표시를 추가하고 기존 장비·각인·보석·카드·아바타·코어 파싱 결과를 재사용했다. 공식 툴팁 원문이 있는 경우 연마·특수 효과·스톤과 개별 젬의 상세를 텍스트로 표시한다. 예리한 둔기와 장비 카드를 같은 좌측 콘텐츠 흐름에 두었다. 착용 장비와 장신구는 넓은 화면에서 2열, 760px 이하에서 1열로 배치한다. 시뮬레이터 렌더러와 계산 요약의 동작은 그대로 사용한다.

캐시에는 기존처럼 큰 응답 원문을 빼고 저장한다. 갱신 직후 받은 표시 스냅샷에는 장비 옵션, 보석 수치와 각인 설명을 함께 저장한다. 이 필드가 없는 기존 캐시는 `powerSnapshot`과 남아 있는 공식 필드로 표시할 수 있으며, 원문 옵션이 필요할 때 기존 **캐릭터 갱신**으로 가져온다. 탭을 열거나 전환하는 작업에서 장비용 API 요청은 추가하지 않았다.

## API 매핑

| 카드 | 데이터와 표시 |
|---|---|
| 착용 장비 | `ArmoryEquipment`와 `powerSnapshot.equipment`의 부위·이름·등급·이미지·품질·재련·상급 재련. 완갑은 관측 시 표시 |
| 장신구 및 팔찌 | `ArmoryEquipment`의 부위별 순서와 툴팁. 귀걸이·반지 각각 두 슬롯. 목걸이·팔찌·스톤의 연마·특수 옵션과 원문 수치 및 기존 효과 파싱 결과 |
| 장착 보석 | `ArmoryGem.Gems`와 `Effects.Skills`의 슬롯 연계. 아이콘·레벨·대상 스킬·피해·재사용 대기시간·공식 기본 공격력 옵션 |
| 장착 각인 | `ArkPassiveEffects`의 장착 각인 등급·레벨·스톤 레벨·효과 설명. 아이콘은 응답에 있는 경우 사용. 확인된 현행 각인 행 대부분에는 아이콘 필드가 없어 자리 표시 사용 |
| 아크 패시브 | `ArkPassive.Points`, `Effects`와 노드 툴팁으로 진화·깨달음·도약별 포인트, 이름/레벨, 효과 |
| 아크 그리드 | `Slots.Gems`의 옵션·활성 상태, `Slots`와 기존 파싱의 활성 코어 효과, `Effects`의 공식 젬 합산, 모델 공통 보정값 |
| 카드 및 아바타 | 카드 각성 및 활성 세트, 아바타 부위·등급·장착 상태·능력치. 카드의 범위가 있는 피해 효과는 조건부이며 아바타는 별도 가산 대상에서 제외 |
| 전투 특성 | `ArmoryProfile.Stats`의 치명·특화·신속·제압·인내·숙련 |

장비 품질 추가 피해와 엔진이 사용한 코어 공통 수치는 파싱된 적용값으로 표시한다. 적용 범위나 발동이 필요한 효과는 조건부, 엔진 매핑 근거가 없는 효과는 미확인으로 표시한다. 툴팁 숫자와 계산용 파생값은 각각의 제목으로 구분한다. 계산식이나 수치 보정은 수정하지 않았다. [공식 Armory 스키마](https://developer-lostark.game.onstove.com/swagger-doc/endpoints/armories)

## 검증

- 공식 API 보관 표본 30직업·60빌드·99캐릭터 전체에서 장비 673건, 장신구 682건, 보석 913건, 각인 496건, 코어 564건, 장착 젬 2,231건, 카드 594건, 아바타 949건의 매핑과 마크업을 대조했다.
- Playwright에서 같은 캐릭터로 1920·1366·820·390·360px의 수정 전후 화면을 비교한다. 대상 카드의 시작 위치, 지면 및 행 오버플로, 카드 열 개수, 상세 옵션 클릭, 신규 검색, 현재 캐시와 구형 캐시, 강제 갱신, 캐릭터 전환, 부분 응답, 미착용과 404 처리를 검사한다. 신규·갱신 요청은 각각 1회였고 저장된 재조회는 장비 추가 호출을 하지 않았다.
- 마나 4차는 99캐릭터의 이론 후보 전부를 직접 전후 열거해 순위와 비교 수치가 모두 일치했다. 캐릭터 분석 변경은 화면과 로컬 캐시의 표시 데이터에 한정된다. 기존 전투·마나·시뮬레이터 회귀는 저장소 테스트로 검증한다.

`scripts/test-character-setup-ui.mjs <Armory JSON> <기준 워크트리> <스크린샷 폴더>`로 대조, 5개 너비별 전후 PNG 및 `coverage.json`을 재현한다. 표본은 보관 응답이고 브라우저의 신규·실패 응답은 재생용 픽스처다.
