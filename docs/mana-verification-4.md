# XXAPICK 마나 엔진 4차 검증

기준 `c72017f` · 별도 Preview 브랜치 `codex/xxapick-mana-verification-4`

## 입력과 적용 범위

- 시간 분석의 기본값은 직접 입력 한 회복 틱이다. 공개 추정 모드를 선택하면 4.44%/초를 수정할 수 있다. 추정 1회량은 최대 MP × 회복률/100 × 틱 간격이다. 시작 MP가 비어 있으면 최대 MP로 시작하고 첫 틱·간격을 비우면 1초 간격을 가정한다. Lv.70 직업별 최대 MP는 자료가 없어 자동 생성하지 않았다. 적용 범위는 독립 시간 분석이다. [공개 추정의 기존 출처](https://www.inven.co.kr/board/lostark/4821/100754) · [출처 검증](mana-verification-3.md#최대-mp-자연-회복-음식룬)
- 민감도 표는 최대 MP ±10%와 회복률 ±0.5%p/초의 9가지 조합을 같은 시전 순서로 재생한다. 시작 MP의 비율을 유지하며 사용자가 입력한 절대량 회복은 같은 양을 사용한다. 시전 조건에 미확인 값이 남으면 해당 조합의 부족 시점과 종료 MP를 보류한다.
- 회복 정보가 없어도 기본 MP, 집중만 반영한 MP, 트라이포드만 반영한 MP, 툴팁 진화 전 비용 및 계획의 진화 후 비용을 표시한다. 기본과 각 옵션의 단독 적용은 확인 가능하더라도 두 옵션의 중첩 비용은 별도의 근거가 필요하다. 시전 조건이 일부 없으면 아는 소모량과 미확인 범위를 구분한다. 최대 MP가 필요한 용광로 추가 비용은 MP 대신 최대 MP 대비 비율을 표시할 수 있다.
- 수지 균형 최소 회복은 계획 총소모/분석 시간이다. 추가 회복 필요율은 `max(0, 계획 소모/초 − 예정 회복/초) / 최대 MP × 100`이다. 순간 부족, 시전 지연, 유효 회복 상한은 기존 시간 엔진에서 처리한다. 음식·서포터의 비교에는 필요한 회복 입력을 요구한다.

## 검증과 공개 근거

- 보관 Armory 30직업·60빌드·99캐릭터·2,394행 재검증에서 자동 시전 대상 837행, 진화 전 비용 775행으로 3차와 일치했다. 99개 캐릭터의 API 파싱 결과는 배포 버전 표기를 제외하고 일치했다. 이론 후보 계산·비교 함수는 동일하며 대표 서머너·바드·리퍼에서 TOP5, 후보 수, 기대 배율의 동일성을 브라우저에서 확인했다. 전체 열거와 점수 입력 대조는 `scripts/audit-mana-top5-diff.mjs`의 `--all`, `--inputs`로 각각 실행한다.
- 공식 툴팁에서 확인된 집중 룬 등급별 감소율, 용광로 최대 MP 2% 추가값, 주요 음식의 자연 회복량 증가율은 3차의 근거를 재사용했다. 음식과 자연 회복의 틱 시점·정수화, 용광로 A/B/C 순서, 음식·서포터 중첩은 검증되지 않았다. 게임 실측 0건. [집중·음식 근거](mana-verification-3.md#최대-mp-자연-회복-음식룬) · [용광로 근거](mana-verification-3.md#용광로-원문-연산-가정-top5)
- 단위 검산 예시에서 12초간 40 MP 3회, 20 MP 2회 비용에 20%·10% 감소를 곱하면 9.6 MP/초다. 1,500 MP × 4.44%/초는 66.6 MP/초다. 이는 계산 테스트에 넣은 제어 입력이다.

## 이용자 관측 자료와 관리자 검토

로컬 JSON 형식의 `version`은 `1`이며 `observations` 배열은 다음 키를 사용한다. `contributor`는 참가자를 구별할 수 있는 가명으로 기록한다. 동일 직업·레벨·패치·장비·전투 상태·최대 MP·회복 조건이 일치한 자료를 묶는다.

| 범위 | 입력 |
|---|---|
| 출처 및 조건 | `source` 영상 등의 식별자, `contributor`, `patch`, `className`, `level`, `equipmentFingerprint`, `combat`, `maxMana`, 선택 `food`, `support`, `recoveryEffects` |
| `ticks` | 발생 `time`(초), `before`·`after` MP. 틱 종료 잔량이 최대치이면 비교에서 제외 |
| `casts` | `name`, 스킬 `level`, `before`, `after`, 기본 `base`, 진화 전 `beforeEvolution`, 감소 후 `reduced`, `reductions`, 연산 `stacking`(`sum` 또는 `product`), `furnacePercent`, 선택 `setup`(집중 등급·트라이포드·노드 등) |

`node scripts/check-mana-observations.mjs observations.json`으로 틱 간격, 관측 회복률, 공개 추정 MP, A/B/C 차감 오차를 비교한다. 보고서는 `PENDING_REVIEW`로 나온다. 검토자가 원본을 확인해 동일 설정에서의 반복을 대조한 뒤 실제 적용 여부를 판단한다. 저장소·운영 Blob에 관측 자료를 쓰지 않으며 관측값 한 건으로 공통 공식을 갱신하지 않는다.
